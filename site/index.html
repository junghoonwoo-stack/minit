THE MODEL

AI builds→minit deploy→your PC runs it→Minit manages it

Small AI-built software often does not need a datacenter. It needs a reliable local runtime and a management layer that removes the tedious server administration.

LOCAL AUTHORITY

Cloud convenience without cloud ownership.

The local machine is authoritative. Optional Minit cloud services are designed for aggregate operational status, fleet administration, alerts, and already-encrypted backup objects — not for hosting the application. Plaintext app code, data, raw logs, secrets, and decryption keys are outside the intended cloud-admin boundary.

INSTALL

Stable sharing today. Local deployment on development main.

PyPI 0.1.0 provides minit run, the temporary local sharing flow. Persistent minit deploy and the local manager are currently on main / 0.2.0.dev0.

# stable PyPI release
pipx install minit-runtime

# current local-manager development version
git clone https://github.com/junghoonwoo-stack/minit.git
cd minit
pip install -e .

TWO MODES

Persistent when useful. Temporary when sharing.

minit deploy means “keep this app running on this computer.” minit run means “temporarily make this already-running local app reachable through a public URL.” Neither moves the application compute to Minit cloud.

# development main: persistent local service
minit deploy --port 8000 -- python app.py

# stable 0.1.0: temporary sharing
minit run --port 8000

PRIVATE BY ARCHITECTURE

The server should not need your app.

Minit's target invariant is that compromising Minit-operated infrastructure must not be sufficient to read protected application/data/backup content or gain privileged control of the local runtime. Remote services may retain minimal operational metadata and ciphertext. Complete zero-knowledge guarantees are not claimed until sandboxing and end-to-end remote-control/connectivity work is implemented and reviewed.

CURRENT RELEASE SECURITY

Temporary public sharing is still public.

The current stable minit run path changes the security boundary of a local app. Treat its generated URL as public and do not use the stable sharing flow for sensitive workloads. Persistent local management and stronger isolation are under active development.
